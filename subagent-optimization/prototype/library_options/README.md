# Library qualification and coverage planning

Local research helpers; no model-facing tool or scientific connector.
Read the [study and limits](../../research/library-alternatives/README.md).

- `curate.py`: verify frozen acquisition/protocol hashes; prepare matched source
  cohorts with existing RDKit. No approval or outcome-based selection.
- `material.py`: run supplied local CReM preparation with one worker and inspect
  reference-context lookups. No candidate assembly or property scoring.
- `index_material.py`: reinspect existing DBs, verify identities and export
  scope-bound lookup keys. No database rebuild.
- `coverage.py`: standard-library greedy maximum-coverage planning with fixed-order
  and largest-library references. It trusts the supplied index and grants no authority.
- `demo.py`: real structural data with hypothetical initial inclusion history;
  no model, native specialist or scientific job runs.

The allowance counts library additions, not compute. Mathematical coverage is
not evidence that products were generated or evaluated. Do not use it to declare
scientific success, exhaustive chemical search or reconciliation of a pending
submission. More lookup coverage is not a scientific endpoint or novel model work.
