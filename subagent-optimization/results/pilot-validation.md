# Conditional pilot validation — 3 November 2026

Historical early-day snapshot. Its 18-test count and implementation hashes predate
the final property-objective pilot. See the [daily summary](../research/progress-2026-11-03.md)
and [publication check](pilot-property-validation-20261104.json) for the later state.

The pilot now provides a reproducible way to test one follow-up library decision
after common observations. It adds frozen requests, persistent attempt receipts,
complete-output assessment, separate arm caches, explicit named-child routing and
recovery of retained results. Scientific execution reuses the existing connector.

The native integration canary uses the separate Agent Scientist SDK and a
disposable profile. Canned loopback responses verify main-policy and named-child
execution, no scientific tool grants, one copy of the role instructions, and
rejection of changed limits or a disabled child. It does not test LLM reasoning.
The initial canary exposed rejection of inherited empty delegation defaults;
that defect was corrected before the passing run.

The portable checks cover strict molecular intake, exact baseline/thresholds,
cache identity, request/library binding, uncertain submission handling, independent
arm state, imported-advice routing rejection and local-only recovery. Exact test
counts, source hashes and the public-reference smoke result are recorded in
[pilot-validation.json](pilot-validation.json).

No generated CReM campaign, real model-inference comparison, profile installation
or scientific improvement is established. Effective inference-setting equivalence,
full compute accounting and live output/model translation still need qualification.
The public task is development material; it does not establish protected-holdout
performance. Numerical resource caps are not enforced by this first runner.

Private run files remain outside the checkout. No commit or push was performed
for this local pilot increment. Publication requires the user's permission.
