# Decision brief: one small-molecule specialist

Tracking: [agent-scientist#33](https://github.com/boltzmannlabs/agent-scientist/issues/33).
Original research: [science-environments#89](https://github.com/boltzmannlabs/science-environments/issues/89).
Date: 2026-11-03. Status: design and offline mechanics; scientific gain untested.

## Problem and evidence

The main agent already constructs scientific payloads, invokes connectors and
interprets results. Existing optimisers already perform search/selection. A new
specialist must justify a better scientific investigation choice, not reproduce
these operations or merely check thresholds.

Two archived development episodes informed this review. The native-proposal
example reached the fixed computational objective in its first batch and should
stop. The later Graph GA tool path completed but returned no qualifying analogue.
Neither episode is a paired specialist comparison or an untouched holdout.
Original task rules and closed/frozen campaign state remain unchanged. Private
job artifacts, candidate files, identifiers and account records are excluded from
this package. The existing research index links the separate environment's
published qualification summary; it is not a specialist evaluation.

Static Graph GA review established that the reference guides similarity while
the initial population comes from a separate pool, bounds enter a reward formula
rather than guaranteeing hard feasibility, output count differs from internal
evaluation effort, and failed predictor paths can leave incomplete evidence.
These observations motivate execution qualification, not a proven remote cause.
In particular, a local zero-similarity fallback is not proof of a GPU outage in a
saved remote run. Engineering repairs must be common to all comparison arms.

## Selected candidate direction

Investigate **context-conditioned selection of an untried fragment library**.
`Fragment_Based_Optimization` exposes a public library input; the inspected CReM
worker uses it to construct the actual fragment database. The optimiser retains
its own enumeration operations. This is a source-supported place for an external
scientific choice, with native readiness and useful assets still pending.

The specialist would use qualified parent-child transformations, local context,
supporting observations and counterexamples to justify the next library. Actual
products must be checked for the intended family: choosing a library does not
guarantee an exact edit, matched panel, site or preserved scaffold.

## What has been implemented

The [offline baseline](../prototype/library_policy/README.md) selects only untried
approved assets, uses versioned reviewed family evidence, preserves original
criteria, binds source results to asset content and rejects incompatible data.
Its controlled artificial histories differ only in observed values: the evidence
rule changes from library C to D while fixed ordering chooses C in both cases.

The [context reference](../prototype/context_contract/README.md) supplies separate
engineering examples for compact evidence, rules, freshness and advisory returns.
Neither module launches a specialist or generates/predicts molecular structures.

The subsequent [local specialist bundle](../specialist/README.md) packages the
reasoning instructions, a native saved definition and checked host handoff.
This is development integration; model reasoning and molecular gain are untested.
It is conditional on meaningful approved alternatives, not a plan to curate
libraries for every target.

## Review-driven corrections

- Reject repeat selection after exhaustive CReM actions: a fixed library is not
  a fresh stochastic exploration arm merely because the caller changes its ID.
- Bind content/version and reviewed capability identity to source batches;
  block renamed equal-content aliases. Different bytes can still normalize to
  identical proposal material, requiring upstream identity/overlap qualification.
- Hold IDs, timing and counts fixed in the evidence comparison, avoiding an
  apparent A-to-B improvement explained by round-robin recency alone.
- Track single/multi-edit annotation conflicts independently of score equality.
  Unknown annotation is a data-quality gap, not fabricated cold-start evidence.
- Separate complete candidate-level first success from full-batch evidence needed
  to build transfer profiles. Unapproved source observations cannot establish a
  protocol-valid success in this helper.

## What constitutes a useful next result

Qualify actual library assets and chemical annotations, then test whether the
specialist's hypothesis-linked choice improves first-success outcomes or resource
use over the simple policy and equally guided main. Include unsuccessful runs,
overhead and internal compute. If no improvement is measured, retain the helper
or same-main guidance rather than assume a separate subagent is necessary.

No scientific improvement, production specialist deployment, calibrated uncertainty,
protected-label isolation or experimental potency is established here.
