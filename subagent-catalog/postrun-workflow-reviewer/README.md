# Post-run workflow reviewer

`postrun-workflow-reviewer` is a manual, read-only SCI specialist. It reviews the whole frozen baseline, locates the limiting stage and chooses one supported change or returns `retain` or `blocked`. The package uses original benchmark-project instructions and fabricated test data, distributed under the [MIT License](LICENSE).

## Run the baseline, then prepare the review

1. Let the main agent finish its workflow attempt. Record the ordered stages, exact tools and typed request parameters, input and output artifact identities, terminal receipts, outcome checks, and time and charges where available. Record absent outcomes explicitly. Keep the original task, controls, cohort and evaluation criteria frozen.
2. Assemble the smallest reviewed text evidence set needed to cover all stages. The packet manifest uses `case_id`, `baseline_sha256` and `evidence` with unique IDs and exact relative file paths and SHA-256 hashes. The baseline digest covers the full workflow snapshot. It carries `task_evidence`, `evaluation_evidence`, `resource_evidence`, `external_inputs`, and a topologically ordered `stages` list. Each stage provides `id`, `engine`, `tool`, `status`, `parameters`, `inputs`, `outputs`, and `result_evidence`. Inputs map documented fields to upstream or external artifact identities. Outputs map documented products to new artifact identities. Separate file bindings from request parameter values. A logical artifact name carries its documented extension when native schema validation requires it.
3. Freeze an operator scope under evidence ID `scope`. Set `workflow_evidence_id`, `catalog` and `options`. For Boltzmann advice, `catalog` names the assigned tool-contract evidence and the assigned sibling files supply native file contracts and input limits. Use the verified catalog for the intended route. Include assigned source documents covering potential alternatives. When no native option is admitted, the catalog can be null. Candidate options are advisory eligibility, and the reviewer has discretion to retain or block. Keep task-fixed or previously rejected settings out of the option set unless the operator has scoped a new comparison.
4. Freeze the exact packet manifest digest before dispatch. Generate the schema with `python3 -B workflow_gate.py PATH_TO_PACKET --packet-sha256 FROZEN_DIGEST` in the SCI runtime with its Boltzmann plugin and JSON Schema dependencies. Supply it through the native delegation task's `output_schema`. Use exact file permissions and a read-only snapshot. Supply the packet manifest and assigned evidence only, without evaluator outcomes, other reviews, source maps or credentials.

## Admit comparable alternatives

- **Parameter change.** An option contains `kind: parameter`, `stage`, `field`, `new`, and `contract`. It changes one existing field of the same wire type. Boltzmann fields must pass the native request checks and limits. For a local stage, the contract enumerates the admitted values under `stages[stage].settings[field]`.
- **Tool replacement.** An option contains `kind: tool_replacement`, `stage`, `new_tool`, `inputs`, `parameters`, `outputs`, and `compatibility`. It must select an active Boltzmann catalog entry. Bind the same frozen input artifacts to the new tool and map its documented outputs onto the same downstream artifact identities. Candidate settings belong to the replacement stage. Provide a compatibility record with `stage`, `old_tool`, `new_tool`, `inputs`, `outputs`, exact `sources` evidence IDs, `assumptions`, and per-artifact `output_checks`. Cover file format, identity, coordinate frame, units, rank or score meaning, and any control requirements that apply. A similar tool name or output format is insufficient. The gate checks structural compatibility and the request. Scientific equivalence and actual file contents require separate verification.

If a potential replacement needs an extra adapter, a different cohort or assessment, or a second stage change, it does not fit this Version 1 one-stage comparison. The reviewer can record the missing requirement for future evaluation. Include all defensible options for the same bounded task to give both reviewers a fair choice.

## Screen and compare

Screen the response with the same command plus `--decision PATH_TO_DECISION`. Also verify that every cited file was successfully read in the scoped runtime. The gate binds a proposal to an exact typed option, requires citations to the stage result, evaluation and governing evidence, and derives the changed stage and its downstream dependents from the artifact graph. Unaffected inputs and outputs can be reused after hash verification. The earlier single-setting apply gate does not authorize a tool replacement.

For a paired pilot, give a clean main-only reviewer and this specialist the same baseline, file set, model, exact alternatives and budget. Freeze their outputs and the primary quality, cost, and preservation criteria before checking results. An independent check and exact operator approval are required before the main agent runs a candidate. Validate actual file receipts against the replacement tool before submission, rerun the affected stages, and use the original evaluation and controls. Report both scientific outcomes and review and workflow costs. If both arms independently choose the same change, evaluate it once and credit both.

## Install and validate

In a fresh SCI profile use `/subagent package install <package-folder> --name workflow-reviewer-test`, review the read-only grants, then start a fresh conversation. Use ordinary native delegation with the frozen packet's exact artifact file permissions and its generated `output_schema`. The operator-side gate uses the SCI development Python environment. The installed reviewer uses only `read_file` and has no skills, child specialists, scientific execution privileges or package-specific credentials.

The release tests include a capacity-limited workflow, a parser-failure workflow offering both a capacity edit and a compatible replacement, and an unresolved job with no approved edit. Compare the verbatim decisions with the expected results and check actual reads and the dependency-derived rerun plan. Run the offline operator tests using `python -B tests/test_workflow_gate.py` from this folder in the SCI development environment. Record managed-install evidence in [tests/validation.json](tests/validation.json). A new SCI version, a differently configured profile or a different model can require retesting.

Assigned evidence reaches the configured model provider when the reviewer reads it. The synthetic test cases use no scientific connector or service and may incur model inference charges. Reviewing a real workflow requires separate approval for its evidence and data destination. Full scientific benchmarks and support for operating systems beyond the recorded test platform remain outside the package validation.
