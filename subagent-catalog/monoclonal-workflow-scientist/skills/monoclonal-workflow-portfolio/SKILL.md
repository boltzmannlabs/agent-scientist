# Workflow portfolio

Use the original request, reviewed antigen dossier, tool coverage and benchmark protocol. Preserve user choices and output requirements. Propose actionable graphs; MAIN executes them.

For multiple workflows, vary a consequential method family, design hypothesis, structural context, sampling strategy or independent validation approach. A changed seed or renamed sequence is not a distinct workflow. Do not impose a universal count, fabricate a reference or force a winner among incomparable evidence.

Each graph names its scientific question, inputs/maps, dependencies, selected tools/versions, adapters, controls, endpoints, resource evidence, stopping conditions, same-operation alternatives and expected artifacts/validation. Use stable workflow/stage IDs so MAIN can import a dependency graph into its task ledger. Link every consequential specialist finding to a stage, control, uncertainty or explicit decision; preserve the original finding IDs. MAIN may add its own task research with separate provenance. Identify disqualifying prerequisites and conditional uncertainty.

Prioritize by task/format/context fit, endpoint evidence, useful diversity, adapter maturity, resources and ability to distinguish hypotheses. Use a bounded discriminating pilot when the evidence cannot decide. Respect user source policy; the default discovery order Boltzmann → ToolUniverse → open source is not an accuracy claim.

Make shared qualified preparation and workflow-specific stages explicit. Reuse identical scientific operations by input/tool/settings identity across branches. Classify ready stages by CPU/RAM/GPU requirements and dependencies so MAIN can overlap compatible local work; do not equate multiple chats, prediction seeds or outstanding service records with parallel distinct workflows. MAIN freezes applicable evaluation and selection rules before inspecting outcomes. Match candidate/reference construct, preparation, sampling and scoring. Preserve raw metrics and predictor disagreement; do not invent affinity by averaging unrelated scores.

Record every proposed workflow and decision. When a selected stage's tool fails or produces invalid outputs, preserve the objective and propose a compatible replacement rather than simply deleting the branch or endpoint. Qualify the replacement against antigen constraints, source policy, pilot geometry, controls and benchmark definitions; label any prospective protocol amendment. Revise only affected unfinished stages and link the old attempt. Do not resubmit an unknown accepted job, regenerate successful stages, silently change frozen criteria or create a competing scheduler. A valid negative result is a scientific outcome, not a tool failure demanding a favorable replacement.
