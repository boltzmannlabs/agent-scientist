# Reproducible scientific harness

Use this skill together with the packaged CRISPR workflow. It transfers execution/evidence discipline, not siRNA models or biological parameters. A consistency check never grants permission or proves native model readiness.

1. Freeze a versioned task/config, model/checkpoint identity, exact inputs, label rule, split/exclusion, metric and uncertainty procedure before scoring. Preserve every attempt. Do not refit or train replacement baselines when the parent selected pretrained-only execution.
2. Separate actual fresh native inference, fresh incumbent control replay, hash-bound cache reuse, identical-input reuse, author-score replay, metric recalculation and software-only probes. Reusing the same target across application frames does not create independent model fits or cohorts.
3. Audit native feature construction before inference. A loadable checkpoint is not a valid pipeline. Missing real context, original chromatin/structure, random placeholder features, unverified weights or a first-row-only CLI are blockers, not permission to synthesize replacements. A fixed seed does not turn random biological features into valid features.
4. Record eval/train mode and random seed. If native dropout is retained, changing subset/order can change the RNG stream; do not call those score changes a checkpoint improvement. Do not silently change mode and present it as exact native replay.
5. Map native outputs by immutable input identity. A CLI's position column can be an ordinal rather than a genomic/transcript coordinate. Validate expected/observed cardinality, strand, PAM/spacer context and coordinate convention independently, then join labels after scoring.
6. Compare the same rows, endpoint and protocol before reporting a matched-protocol delta. Record threshold conventions literally, including strict versus inclusive cutoffs. Different cohorts, clinical outcomes, drug/site anchors or model-specific score units are contextual evidence, not interchangeable ground truth.
7. Preserve blocked and failed stages with null/unavailable performance, never zero scores. Keep partial attempts and software probes in history, outside the completed-only benchmark tree. A completed native endpoint can be published with explicit scope even if the broader application remains partial; name the exact completed stages.
8. Use the leaf package's schema-version-2 run-record contract and harness audit CLI, supplied by the parent. The optional harness dependency profile enables JSON Schema validation and raster checks. Artifact reads require explicit verification plus an approved artifact root. These tools and schemas belong to the leaf package, not this procedural skill folder; ask the parent for them if absent. Never interpret data flags or checker success as consent to read or upload files.
9. Verify real commands/exits, data/model/config hashes, joins, counts, original-source preservation and decoded raster artifacts where relevant. Raster decoding/nonconstant pixels are not visual inspection or biological validation. Use fresh run directories and independently verify final manifests.
10. Return unresolved permissions/inputs to the parent. Do not ask for a new run name, install into SCI, alter another profile, mutate shared imported run globals, silently switch providers or duplicate a pending remote job. Keep experimental_validation=false and best_design=null.
