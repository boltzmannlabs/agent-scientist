# Harness integration and evidence boundaries

## Domain boundary

This package remains a CRISPR/gRNA specialist across its thirteen declared application classes. Transfer reproducibility lessons from RNAi campaigns, not RNAi predictors or sequence conventions. An siRNA/RNAi request belongs to a separately reviewed RNAi specialist; it is not a Cas13 assignment. No siRNA model dependency is added to CRISPR activity, editing or specificity profiles.

## Run workflow

1. Parent resolves target, modality, exact scientific contract, sources, provider, permitted roots and isolated interpreters. Metadata fixtures are not authorization.
2. Run request_contract.py. Preserve exact identifiers. Its result follows request-result.schema.json, not the scientific run-record schema. Invalid/out-of-scope requests stop dependent work; missing inputs return to the parent.
3. Review model source/weights/native inputs and feature construction. Record observed software availability separately from verified native fixtures and scientific applicability. A successful version/import/checkpoint load is not native inference.
4. Freeze task-indexed config and input hashes. Execute the requested authorized native endpoint, preserving raw output, command, exit, inference mode and mapping. A new run must not overwrite prior results. Maintain caches and disposable execution trees only under approved roots.
5. Write run-record schema v2, then run the offline evidence auditor. Structural JSON Schema checking is optional through the harness QA profile; semantic consistency is standard-library-only. Checks never execute the listed scientific commands.
6. Publish only a finished verified native endpoint in benchmark/. Keep blocked setup, software probes, controls without measured native endpoints, author-score-only reviews and failed attempts in history/. Preserve scientific caveats with completed native results. Publish no synthetic fixture as a measured result.
7. Hand back counts, execution classes, per-endpoint source/units, limitations and exact artifact paths. The parent verifies claimed external effects and owns publication/approval decisions.

## Readiness and comparison checks

Block unseeded random replacements for learned biological inputs, synthetic flanks, imputed chromatin, dummy coordinates, incomplete output cardinality and silent model substitutions. A published article does not establish accessible code, weights, licensing, reference files, feature pipelines or a runnable service. Inspect access responses: HTTP 200 HTML/sign-in pages are not archives. A visible GPU is not proof of framework compatibility.

Declare fresh native inference, native control replay and each cached/identical-input/author-score reuse separately. Record actual unique cohorts; copied task frames do not add independence. Native active dropout can make a fresh subset disagree with full-pool history despite a fixed seed. Retain that limitation rather than presenting a performance gain.

Use null matched_protocol_delta unless cohort, endpoint and protocol are genuinely matched. Public measured-label evaluation is distinct from reproducing an author's exact model benchmark. Original assay labels must remain unchanged; document inclusivity of cutoffs and censoring. Record training exclusions, previous test-label exposure and small/degenerate subgroup limits. Do not promote a same-label selected winner as independent improvement.

## Record migration

run-record.schema.json now requires schema_version=2, run_id/config_id, stage execution_kind, provenance, comparison, benchmark and publication metadata. Old v1 records are not silently normalized: archive them and derive a v2 record with explicit unknown/blocker values from actual evidence. New required hashes must be measured from approved artifacts, never invented. Metadata/package checks can use publication=history or not_applicable and measured_labels=false. See tests/synthetic_harness_record.json for an inert example, not a scientific result.

request-result.schema.json separately covers invalid, out-of-scope, review-only and missing-input preflight responses. This fixes the previous mismatch between a request rejection and a scientific run record.

## Dependency and installation limits

Core scripts/tests are standard-library-only. The optional harness environment provides jsonschema, PyYAML, packaging and Pillow for QA; native CRISPR interpreters and model assets remain separately reviewed dependencies. Observed requirements are not complete transitive locks or clean-install guarantees. Do not merge legacy TensorFlow, PyTorch, Python2 and modern analysis environments.

Updating this source package does not update an already installed specialist or cached conversation. Use the locally supported reviewed package-install flow and a fresh session; do not assume a shell `sci subagent` command exists. Parent-project legacy build/validation scripts can target older package versions; do not rerun them to overwrite this revision. Use the packaged validation script for this revision instead.
