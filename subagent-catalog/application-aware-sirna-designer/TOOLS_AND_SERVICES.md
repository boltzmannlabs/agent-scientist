# Tool and service boundaries

Built-in read/search/write/patch tools support approved local files; terminal/execute_code support explicit approved setup and adapter execution. skill_view loads procedural guidance. These are host capabilities, not a filesystem or network sandbox. The package cannot grant clarify, nested delegation, credential/config management or unrestricted egress. Missing decisions go to the parent.

Optional Boltzmann integration declares maintained RNA generation and property-prediction modules. SCI setup/authorization is parent-owned. Exact historical catalog jobs include rna_siRNA_gen, rna_siRNA_efficacy_pred and siRNA_obj_pred; refresh complete contracts before use, including files, required GC bounds, partial validation and provider costs. Model metadata must be checked from returned artifacts; do not assume a remote efficacy tool is RN.Ai. Submit once, retain job/document IDs and poll the same job. Do not interpret a platform Success status as correct outputs. Download through the connector to its default persistent destination unless the user chose a location. No direct internal API invocation or shadow service client is supplied.

No external MCP is required or bundled. PubMed/Ensembl/ClinVar/GTEx/HPA/OpenTargets retrieval is conditional parent work using their actually available tools and source/egress approvals; tool names, counts and credentials are not hardcoded from historical ToolUniverse installations. Missing services block their dependent context, not the whole core audit. Local alternatives are only used after actual provider decision/approval, never as a credential/authentication bypass.
