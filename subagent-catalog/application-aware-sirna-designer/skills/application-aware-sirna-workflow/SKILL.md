# Application-aware siRNA workflow

1. Follow parent safety/provider/permission policy; support noninfectious human research, not infection-enabling, pathogen, pest or unreviewed organism design.
2. Select an explicit application and mode. Require exact target/transcript, isoform/coverage objective, contextual endpoints, reviewed budgets, frozen gates, a confirmed requirement brief and real native readiness.
3. DESIGN/EXPLORATORY use an authorized native generator then relevant battery; EVALUATE runs only requested properties; BENCHMARK freezes labels/exclusions before scoring. Missing inputs return to the parent; never ask for a run name.
4. Preserve exact input representations and original references. Native APIs may use ordinals, active dropout or context assumptions; verify them rather than reinterpret values.
5. Keep efficacy endpoints independent. Rank with one explicit native efficacy endpoint and implemented dimensions only; no legacy score blends, hidden zero-weight components or silent renormalization. Hard gates precede weight sensitivity and seed/site diversity.
6. Keep formulation, chemistry, reporter and tissue context distinct from actual efficacy/delivery. Variant/CNS/orthogonal requirements block unsupported full-application claims.
7. Save all tried configs, raw scores, gate reasons, missingness, hashes and trajectory plots under fresh approved roots. Return fewer survivors rather than fabricated/padded panels. Computational panels require experimental validation.

Read [application map](references/application-map.json) and [endpoint rules](references/endpoint-rules.md). The parent's leaf resources supply the concrete harness, schemas and frozen gates; no scientific model is bundled in this procedural skill.
